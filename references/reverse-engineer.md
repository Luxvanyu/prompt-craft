# 反推：从一张图回到提示词

> 反推不是「看图说话」，是**两次测量 + 一次翻译**。
> 眼睛负责结构（谁在前、谁在后、什么形状），脚本负责明度与色彩（多亮、多艳、多大面积）。两者不能互相替代。

## 零、四条纪律

1. **肉眼看结构，脚本看明度。** 实测两次都栽在这上面：一张图的暗部肉眼像「接近黑」，`probe` 一量 `p1 0.162`；一片蓝肉眼看是「钴蓝」，取中位色是 `#3462AB` 的钢蓝，而按「钴蓝」写出来的是 `#1B70F6`。**数值不撒谎，印象会。**
2. **参考图不是规则。** 单张图只能给「这一张的事实」。要写成「这类图如何」，得 6 张以上且覆盖不同主体与光照（见 `aesthetic/h-style-extraction.md` 的证据分级）。
3. **看不清就写低粒度。** 写 `a small pale ornament` 而不是猜成「银质玫瑰胸针」。猜错比模糊更伤，因为模型会认真把猜的那件画出来。
4. **脚本答不了「她在干什么」。** `probe.py` 给的是亮度和饱和度，给不了动作、位置、运动方向。所以第一步是**看画**（第一节五个问题），不是跑脚本。脚本负责校正眼睛，不负责替眼睛。

---

## 一、看画那一半：五个问题（脚本看不见的东西）

`probe.py` 只回答「多亮、多艳、多平」，它回答不了「她在干什么」。一张图能不能反推对，八成在下面五个问题里，而且必须在动笔之前用眼睛答完。

| # | 问题 | 要答到什么程度 | 脚本能帮上的 |
|---|---|---|---|
| 1 | **谁在做什么，做到哪一步** | 动作进行到一半（手臂还在抬／头刚转过去）；身体哪几处在承重；两只手分别在哪、在干什么 | 帮不上 |
| 2 | **东西在哪** | 分三层：贴近镜头的（大、暗、边缘糊）、中景（清晰、细节最多）、远景（小、淡、被光吃掉）；每层说清谁挡住谁 | 6×6 网格只给亮度分布 |
| 3 | **怎么动的** | 不写「动感」。找依据：头发与衣角朝哪、碎片朝向、拖影在哪一侧、边缘是刀切还是糊 | `strong` / `flat` 提示边缘硬度 |
| 4 | **光从哪来，落在哪** | 唯一亮源在画内还是画外、照到哪几个面、没照到的地方有多深；有没有第二个光；色散／bloom／烟是**光的后果**，不是独立元素 | `p1` `p99` `nw` `dark` |
| 5 | **有没有一个不对劲的地方** | 接 `eye.md` 第一节：不该在那里的、或该在却不在的 | 帮不上 |

**产出格式：五句话，一问一句。** 五句话写不顺，说明还没看清，这时候写出来的必然是「一堆光效形容词」。

### 看不准怎么办：五道手续

先承认一件事：**「看画」是这套流程里唯一没有工具兜底的环节，而它决定全部下游。** 提示词写得再准，看错一处就全废。所以它必须像脚本那样有手续，不能靠「我看了」。

看错只有三个原因，每个都有对应的手续：

| 错因 | 表现 | 手续 |
|---|---|---|
| 看的是**降采样图** | 1200×1932 的图到眼里只剩 990 宽，手指数都数不清 | **切块放大**，一次只看一块 |
| 从**先验**补全 | 「动漫图里这种姿势通常是……」于是写出图里没有的东西 | **不确定清单**先写，看不清就写低粒度 |
| 把猜的写成**肯定句** | 句子读起来很确定，其实没依据 | **反读校验** + **盲读比对** |

#### 手续一：切块放大，一次只问一个问题

```bash
python scripts/crop.py REF.png --grid 3 --out ./crops            # 九宫格（自带 12% 重叠）
python scripts/crop.py REF.png --region hands,0.05,0.55,0.45,0.85 \
                              --region face,0.30,0.10,0.60,0.40    # 指定局部（比例坐标）
```

规矩三条：

- **放大到长边 900–1100 像素再判断。** 小于这个尺寸的细节，宁可标「看不清」。
- **一块只回答一个问题。** 不是「描述这一块」——那是给印象，不是给事实。要问「她的左手在哪」「那个红色的是布还是漆」。
- **先看整图定层，再看局部定细节。** 反过来会陷在某块里，丢掉整体关系。

#### 手续二：先写不确定清单，再写提示词

动笔之前单列一段：

```text
看不清：她左手在做什么 / 腰后那根白的东西是烟还是绑带 / 蓝色生物是一整个还是只有半个身子入画
```

三条规矩：

- **看不清的地方写低粒度**（`a small pale ornament`、`a dark strap`），不猜成具体物件。猜错的代价比写糊大得多——写糊只是弱，猜错是错。
- **清单上每一条都要决定「写还是删」**。既不能留空让模型自己补（它会补一只手），也不能硬写成具体的东西。
- **清单本身就是诊断**。超过五六条看不清，说明这张图的信息量超出可复刻范围，该主动告诉用户「这张我只能复刻到六成」。

#### 手续三：二十个硬问题，不许问「画面是什么」

「画面是什么」只能得到形容词。要问**离散、可验证**的问题，每个答案要么给证据，要么写看不清：

| 组 | 问题 |
|---|---|
| 人物 | 几个人形角色／占画幅多少高／**脸看得见吗**／几只手指认得出／每只手在握什么／哪条腿在前／身体朝向依据哪条布料的走向 |
| 道具 | 几把刀（刀身还是刀鞘）／火有几处／刀在手里还是悬空／白色烟雾状的东西在哪、几条、什么形状 |
| 第二角色 | 独立角色还是贴着主角／几只翅膀／脸朝向／穿没穿衣服 |
| 空间 | 主角在建筑前还是后（依据）／哪一处能看出地面／能读出的文字有哪几处 |
| 光 | 单一光源还是漫射／影子往哪倒／最亮的一小块在哪／最黑的一块在哪 |
| 动势 | 定格还是拖影／拖影在哪几块、朝哪个方向／整体倾角多少度（依据） |

**「脸看得见吗」必须排在最前面。** 它是整张图最贵的一条信息：有脸就要写表情、眼神、五官朝向；没脸就要写死「画面里没有脸」，否则模型一定给你转一张正脸过来。

#### 手续四：反读校验

写完提示词，**把参考图关掉**，只读自己的句子，逐句问一句：**按这句话画出来，会长成那张图吗？**

- 每句标 ✓／✗／?。
- 所有 ✗ 回去看对应的裁切块，改句子。
- 所有 ? 进不确定清单。

这一步抓的是「我以为」——写的时候脑子里有图，读的时候没有了，落差就是错误。

#### 手续五：盲读比对（最有用的一个）

让**另一个没有上下文的模型**只拿图和同一套二十问，独立读一遍，然后跟自己的答案逐条对比。

- 两份答案**一致**的条目 → 可以直接写进提示词。
- 两份答案**不一致**的条目 → 就是真正看不清的地方，必须回去看裁切块，或者降粒度。
- 对方**看出而我没写**的 → 通常是「我根本没注意」，这是最值钱的发现。

一个模型自己读两遍没用——两遍会用同一套先验补同一个洞。要有分歧，必须换一个没有兴趣的读者。

`scripts/look.py` 就是这一道手续的工具化：把图（或裁切块）连同内置二十问发给一个视觉更强的模型，要回来的是一行一条、每条要么可核对要么写 `UNCLEAR` 的答案。

```bash
python scripts/look.py REF.png --sop                  # 二十问一次读完
python scripts/look.py REF.png -q "左手在哪？握着什么？"
python scripts/look.py crops/Ghip.png crops/Ghead.png -Q questions.txt
```

它的价值不在「更准」，在**换了一个错的洞**。实测一张图，两边各错各的：我对了三处、它对了三处；只在它写 `UNCLEAR` 的地方，两边才会一致地承认看不清——那种地方就该降粒度，别硬写。

### 例子（2026-11-18 那张竖向动势图）

1. **谁在做什么**：她站在一条细栏杆上，身体顺着世界的倾斜；一只手还抓在梯级上（是在稳住，不是摆姿势），另一只手张开空着；头低下向右看。头发被整股向上拉起——所以气流是向上的。
2. **东西在哪**：近景是右下几百片黑三角（最大、最黑、边缘最硬）；中景是她与栏杆；远景是白 bloom 和压在它前面的烟；一块玻璃巨板几乎侧立，横切左半，切口从左上一直落到右下。
3. **怎么动**：黑三角沿一条斜轴排开，越靠近镜头越大；头发朝上偏左；裙摆被压平贴腿——风从右边来、往上走；那六七个玻璃立方体不跟着飞，它们悬着。**两种运动并存**（碎片被甩、立方体悬浮），这一点光看「有碎片」是看不出来的。
4. **光从哪来**：唯一白 bloom 在中间偏右、藏在黑刃后面；色散只出现在玻璃切口上（紫／品红／青）；左下角完全没有光。
5. **不对劲**：梯子没有尽头，她站在一条通向虚空的栏杆上；立方体悬着不合物理。

### 一个只有脚本才看得出的反例

这张图肉眼第一眼是「色彩丰富」——紫、品红、青、蓝都在。实测 `sat 0.070`，是**几乎单色**：整张就是灰黑白，彩色只存在于那道切口上一根发丝宽的地方。

要是按眼睛的印象写 `iridescent, prismatic, rainbow sheen`，`sat` 会像上一张海报那样从 0.16 窜到 0.28。所以写成了 `nothing else in the frame carries colour at all, the rest of the picture being grey, black and white`。

**一句话：眼睛定「哪里有色」，脚本定「有多少」。**

### 换画幅时改什么（竖 → 横）

同一个内容换到 21:9，动的不是句子，是**分配**：

| 竖构图 | 21:9 横构图 | 为什么 |
|---|---|---|
| 两块暗体上下夹住亮带 | 改成左右夹：玻璃板压左侧、黑刃压右侧，中间留一条白走廊给人物 | 横画幅没有「上下中段」，只有左中右 |
| 世界倾斜 30° 以上 | 收到 18° 左右 | 横画幅里陡角把画面切成两半，人会被挤到角落 |
| 人物占高 1/7、宽 1/13 | 高 1/6、宽 1/13 或更窄 | 横画幅里人容易「变胖」，宽度要单独写死 |
| 碎片自上往下落 | 沿同一斜轴横向排开，近大远小 | 运动方向要顺着长边，否则碎成一团 |
| 手搭在**贴边**的东西上（栏杆、桅杆、机柜） | 先问「横版里那件东西还在手边吗」；不在就把这个接触**删掉**，改成手在自己身上或有明确支撑 | 距离一变，接触链就断了，模型会自己补一只手去够 |

落进句子的写法：`the world itself is rotated about eighteen degrees, so the long straight edge of the glass runs in from the left border a third of the way up and falls away to the lower right corner`。

> ⚠️ **换画幅第一个要重算的不是构图，是接触链。** 2026-11-18 那张宇宙投影就是当着这个坑栽的：竖版里她一只手抓着结构杆、一只手抱着投影仪，都在手边；改成 21:9 后我把飞船外壳推到左边缘、她挪到中偏左，那根杆子仍然写着「从她左上出框」，但实际要跨过半个画面才够得到。模型的处理方式是**给她补一只手**——返图里她背后多出一只手。
>
> 横改竖、竖改横都要把这张表过一遍：**手够得到什么、脚踩着什么、背靠着什么、被什么挡住**。够不到就改写（让手改抓自己肩带、改成掌心贴着自己膝盖），不要留着旧句子赌它能圆。
>
> 顺带一条写手的通用口径：单人拿大道具时，**两只手各自的落点要写死到「哪只手套在哪个位置、手指在做什么」**，并且把道具的承重写成「压在肩上 / 抵在小臂上」而不是「抱着」——`抱着` 这种词会让模型觉得还缺一只手扶着。

## 二、先跑三个数（三十秒）

```bash
python scripts/probe.py ref.png
```

一次给出：`size / mean / med / dark / mid / bright / nw / p1 / p99 / rgb / sat / lit / shadow / soft / strong / flat`，外加 6×6 明度网格与 hex 采样。

| 数 | 在说什么 | 怎么用 |
|---|---|---|
| `mean` `med` | 整体亮度 | 决定明度档，**不要凭感觉定高调/低调** |
| `dark`（<0.10） | 近黑占比 | 0.00–0.02 = 这张图没有黑；别再写 `near-black` |
| `p1` / `p99` | 最暗/最亮的 1% | 反推「暗到哪、亮到哪」的边界；`p99 0.95` 说明白停在纸白，没到纯白 |
| `nw`（近白占比） | 白有没有糊 | 参考图常是 0.01，写错就变 0.4——这一项最能暴露「白」被写糊 |
| `sat` | 整体饱和 | 决定色数：0.15 左右通常只有一个饱和色 |
| `soft` / `strong` | 平缓/陡峭梯度占比 | `strong` 高 = 硬光多；低 = 全散光 |
| `flat` | 平坦区占比 | 平涂设计类会到 0.7–0.8，写实类通常 0.4–0.6 |
| 6×6 网格 | 亮度分布在哪 | 找「光从哪边来」「哪块是空的」 |
| hex 采样 | 实际色号 | **反推色彩唯一可靠的依据** |

## 三、分层（顺便决定 Caption 还是 Layout）

把图拆成四层，每层记三件事：**占画幅多少 / 边缘什么行为 / 明度落在哪一段**。

| 层 | 典型内容 | 反推时要记的 |
|---|---|---|
| 底 | 纸、墙、天空、地面 | 占比、最亮还是次亮、有没有纹理 |
| 平面层 | 色块、线、字、印刷元素 | 形状、边界朝向、是否带透视、覆盖率 |
| 主体 | 人、物、巨物 | 宽高比、朝向、光落在哪几个面 |
| 叠加 | 碎片、雾、颗粒、光效、介质 | 数量、方向、只出现在什么地方 |

**默认出 Layout，不是 Caption。**（2026-11-18 用户明确要求：反推一律先给 Layout 草稿。）理由是反推要动的东西全是「哪块在哪」，而 Layout 是唯一能把这些位置写成数字的形态——Caption 里一句 `right of centre` 到底偏多少，模型只能猜，猜出来就是错的。只有用户明说「要纯文本 / 给我 caption」时才走 Caption 那条路。

Layout 反推的组织方式：

- `summary.caption` 只承担**全局**的事：明度档、机位四要素、光照归属、色相分区与各自占比、收尾两处锚。局部细节全部下沉到 item。
- item 按**层**切，不按「东西」切：远景一层、中景一层、近景一层、前景结构一层、人物一层、要出字的地方各自一层。
- 每层都要写它自己那一段的**明度与边缘行为**（这一层是压黑的、还是亮的；边缘是刀切还是散开的），否则各层会被统一成一个亮度。
- 有真实文字就单独 `text` 框，一处一个，不要合并。

判断「要不要 Layout」只在一种情况下有意义：用户要的是纯文本，而你判断这张图非 Layout 不可——那就先说明为什么，再给 Layout。

> 提醒：画面细节多**不等于**需要 Layout。官方原话是「A detailed image does not automatically need Layout」。但反推是另一回事——反推默认就是 Layout。

### 3.1 元素框对齐核验（有参考图的复刻才走这段）

适用条件：**手里有参考图、且已经决定出 Layout**。无参考图的原创构图、或这一张只出 Caption，没有框可对，跳过本节直接 `lint.py`。

这套动作来自第三方工具 liangci-ai/MOSS-YXBOX 的几条经验，本包拿它当助手而不是标准：`GRID=16` 是 MOSS latent 的硬约束（这条成立）；`MIN_BOX=16`、背景到前景的重排顺序、主色个数是启发式（这几条换个模型要重新标定）。所以照跑，但结论自己核。

六步（第 1–2 步是准备，第 3–4 步出稿，第 5–6 步核验）：

1. **按比例算分辨率**：`python scripts/align_bboxes.py dims REF.png`，默认基准面积 1536×1024、长边上限 1664，输出最贴近原图宽高比的 16 倍数尺寸，省掉手算。
2. **铺网格精确读框**：`python scripts/align_bboxes.py grid REF.png -o grid.png` 在原图叠 10% 坐标网格（50% 处是黄色中线），照格读比例坐标，不靠目测估算。
3. **拆细紧贴局部框，禁后置全屏大框**：关键道具、独立角色、独立文字块各自拆成紧贴边界的框；全局环境交给 `summary.caption`，别在角色后面塞 `[0, 0, W, H]` 兜底 `object` 框（`verify` 会报「覆盖画布 100%」）。
4. **16px 吸附 + 背景到前景排序 + 主色采样**：`python scripts/align_bboxes.py verify DRAFT.json --ref REF.png --out-draft ALIGNED.json --out-overlay OVERLAY.png --extract-palette`，自动做 `GRID=16` 吸附（挪超过 8px 会告警，提示你原始坐标读错了），按**背景/大物件 → 局部道具 → 角色主体 → 前景/文字**重排 `items`，并从原图框内按像素占比采样主色写进 `palette`。
5. **背景文字防压脸**：墙体大字、街道招牌这类在人物背后的文字，跑 `verify` 时加 `--bg-text "关键词"`，或在草稿该项写 `"z_layer": "bg"` —— 后者比子串匹配可靠（同名词出现在前景 HUD 里不会被误沉到底）。`z_layer` 是对齐工具的工作标记，`verify` 会剥掉它；`compile_prompt.py` 也认这两个值并跳过，不会报 unknown fields。HUD/对话框/前景标题要置顶就写 `"z_layer": "fg"`。
6. **叠框目视复核再编译**：看 `OVERLAY.png` 确认红/蓝/黄框紧贴原图对应元素、没有错位遮挡，再跑 `lint.py`（固定角色复刻加 `--swap`）与 `compile_prompt.py`。高频构图与角色替换细则见 `references/reverse-patterns.md`。

## 四、色彩反推：要色号，不要色名

同一个「蓝」，三种写法落点差很远（本次三张实测）：

| 写法 | 实际落点 |
|---|---|
| `cobalt` | `#1B70F6`（电光蓝，`sat` 被抬到 0.28） |
| `sky blue` | `#4A98FC`（更亮，偏天蓝） |
| `a dull printing blue, the colour of water on an old map, two steps darker than electric` | `#3462AB`（接近参考图） |

规则：

1. **色名后面跟一个参照物**（印刷油墨、旧地图、铁皮、雾里的灯），比只写色名稳。
2. **覆盖率用比例写，不用形容词。** 参考图蓝块占 9.4%，写成 `a large blue shape` 会得到 20.8%；写成 `covering about a tenth of the frame` 才收得住。
3. **色数由 `sat` 定。** `sat 0.15` 左右就只给一个饱和色，其余写灰白；点到三个色，`sat` 会跳到 0.27。
4. Layout 里可以把实测色号写进 `palette`，但**不要指望它能压住饱和**——那句话仍要在 caption 里说。

## 五、七维翻译（每维只写「能被画出来的那件事」）

| 维度 | 图上看到的 | 译成什么 | 别这么写 |
|---|---|---|---|
| 明度 | 整片亮、暗只在几处 | `high key, and the deepest tone is …` + 暗块点名 | `bright and clean` |
| 光 | 光从一侧来、边缘像刀切 | `one light, from the left; every shadow edge is cut like a blade with no gradient` | `dramatic lighting` |
| 空间 | 人物在前、色块在后 | 一句遮挡链：`the sleeve cuts across the band` | `layered composition` |
| 色彩 | 一个饱和色 + 灰白 | 色号 + 参照物 + 覆盖比例 | `colourful` |
| 材质 | 羽毛有窄高光、袖子半透 | 材质的**可见行为**：`one narrow specular line down each shaft` | `detailed feathers` |
| 瞬间 | 头半转、嘴微张 | 一个主动作 + 它的物理结果 | `dynamic pose` |
| 收尾 | 画面止于哪里 | 一句「最暗/最亮落在哪」封口 | 堆形容词 |

## 六、三处必须写死的锚

反推时最容易漏、漏了画面就走形的三件：

1. **最亮的一点**落在哪个具体材质上，且**只有一处**。写 `the brightest single point is the line down the leading feather`，不写 `bright highlights`。
2. **最暗的一点**是什么、有多深。别默认 `near-black`——先看 `p1`，0.16 就写 `a slate blue`，写 `near-black` 会把前景压死。
3. **主体的宽高比**。宽度比高度更能控体积：`no wider than a fifth of the frame, standing the full height` 比 `a large figure` 精确得多。

## 七、出图后：差值 → 改哪句

这是整个模块最值钱的一格。拿返图跑一次 `probe.py`，对着参考图逐项看：

| 差值 | 说明 | 改哪一句 |
|---|---|---|
| `mean` 比参考高 0.08+ | 整体偏亮 | 明度定调句：把「最亮的大面积」降为次亮，把最亮让给具体材质 |
| `nw` 比参考高 0.2+ | 白糊成一片 | 删掉 `white` 类词，改成「纸在阴影里的那种灰白」+ 一个参照物 |
| `p99` ≥ 0.99 | 顶到纯白 | 高光只留一处，其余写「差半档」；白面写 `off-white` |
| `sat` 比参考高 0.05+ | 色太艳 | 减色数：只留一个饱和色；把色名换成带参照物的写法 |
| `sat` 比参考低 0.05+ | 色太灰 | 给**最大面积的面**挂色相词，别挂在小道具上 |
| `flat` 比参考高 0.08+ | 太平、层次糊 | 补边缘硬度 + 材质可见行为；或缩小色块面积 |
| `flat` 比参考低 0.08+ | 太碎 | 加「大面积均匀」的句子，减碎片与纹理 |
| `strong` 明显偏低 | 硬光没出来 | 写 `shadow edges cut like a blade, with no gradient at all` |
| `dark` 比参考少很多 | 暗部不够 | 点名 3 处暗块 + 各自深度，**不是**加 `near-black` |
| 主体明显偏大/偏胖 | 比例失控 | 写宽高比，并把这句移到主体句旁边 |
| 文字变大变清楚 | `text` item 字号过大 | 缩小 bbox 高度；caption 里加 `small enough to read as texture, not as words` |

反过来的用法也成立：**差得最小的那几项，说明那几句写对了**，下一张可以照抄那几句的写法。

### 7.1 「七七八八，但光效没渲染出来」——看 flat 与 strong

2026-11-18 那张竖向动势图，用户看完返图说「也七七八八了，差点光效渲染的样子」。这句话能直接翻成两个数：

| 指标 | 参考图 | 返图 | 读法 |
|---|---|---|---|
| `flat` | 0.496 | **0.760** | +0.26：平的像素多了一半 |
| `strong` | 0.189 | **0.073** | −0.12：硬边掉到四成 |
| `soft` | 0.811 | 0.927 | 整张被磨软 |
| `dark` | 0.070 | 0.199 | 碎片反而更黑更实 |

四个数一起看只有一句话：**介质没有形成层次，被画成了一块平的亮面。**
原因不是「光写得少」，是写得**太弥散**——`a wide bloom`、`a soft veil of dust`、`a faint chromatic band` 这类写法，模型就给你一块均匀的亮区或彩色区。要出层次，得换成有边界的写法：

| 别写 | 写成 |
|---|---|
| `a wide bloom of white` | `the bloom has a hard outer boundary where it meets the paper, and inside it the white steps down twice` |
| `a soft veil of dust` | `the dust sits in three separate layers at three distances, the nearest reading a full stop darker` |
| `a faint chromatic band along the edge` | `the colour exists only on that one edge and nowhere else, running magenta at the near end and cyan at the far end` |
| 「光的某种效果」（名词） | 落点 + 形状 + 分几层 |

单独记一条：**色不在光里，色在光落到的物体表面上。** 见 8.3——楔形光束内部全黑，彩色只出现在光束切过月球的那块面上。模型对「空中的彩色」几乎无感，对「被照到的面上的彩色」很敏感。

### 7.2 一件大道具的三视图陷阱（透视被画错）

2026-11-18 刀锋特写那张，返图给的差值是 `strong 0.074`（参考 0.262）、`flat 0.735`（参考 0.440）、`p1 0.125`（参考 0.059）——线全糊了、层次没了、该黑的地方没黑。但用户点出的第一句是「**完全写错了透视**」，而透视错误在数值上只表现为 `strong` 偏低。

看画面：一把刀被画成了**三个视角**拼起来的东西——护手是正对着看的，护手下面那块铜箍是斜四十五度看的，刀身却是近乎平视、从顶到底等宽没有收分。三个部分各自都合理，合起来不是同一件东西。

根因是我只给了刀的**二维落位**（`its flat runs from the top edge down to the bottom left corner`），没给它的**三维朝向**。当一件道具占掉半个画面、而描写只够还原它的剪影时，模型会分别给每个零件安排一个看着最顺的视角。

修法（写在一句话里，别拆成三句）：

```
the whole sword hangs in one plane: the flat of the blade is turned a little toward the viewer and its axis leans about fifteen degrees off vertical, the guard sits square across that same axis with its face toward us, the copper collar wraps the blade's base in the same plane, and every one of them foreshortens together
```

三件事一起写才对：**①刀面朝谁 ②中轴与竖直成几度 ③护手/铜箍/刀身在同一平面上一起收分**。再补一句「只有这个角度才看得见的事实」——比如刀面半侧着时能看见刃口的白线、看不见刀背的厚度——把视角钉死。

顺带两条同源教训：

- **线稿题材要给「线优先」的物理事实**：`every form is bounded by a drawn line before any wash is laid on, and those lines stay crisp and dark no matter how pale the wash gets` + `no airbrushed transition anywhere, every edge is either a drawn line or a hard wash boundary`。只写「细墨线 + 淡彩」不够，模型的动漫先验会把线条磨成柔光（`soft 0.738 → 0.926`）。
- **暗部要有具体归属**：`p1 0.059 → 0.125` 说明护手凹槽和底边落花都没压下去。写「最暗的两处」时要点名它们在哪个零件上，而不是写一句 `the darkest thing`。

### 7.3 人放错位置、放大一圈：位置句要钉在物件上

2026-11-18 魔法阵那张，反推整体成立（`dark 0.203→0.192`、`soft 0.794→0.788`、`strong 0.206→0.212`、`flat 0.591→0.560` 全部贴合），用户只挑出两处：**人物位置不对、尺寸偏大**。

我写的是 `right of centre` + `a little under two fifths of the frame height`。落成：**几乎正中 + 约一半高**。

两条规律：

1. **`right of centre` 会被读成「就在中间偏一点点」。** 模型的默认先验是把人放正中，你说偏右，它只偏一点。要把位置钉死，得先**把画面中线交给一个具体物件**，再说她在中线哪一侧、多远：
   - 先写：`the vertical centre line of the frame passes through the beast's open jaw`
   - 再写：`her helmet sits about a fifth of the frame width to the right of that line`
2. **高度会被放大约一成。** 与「覆盖率」同源（写 10% 落成 21%）。想要 40% 就写 `a little over a third`，并且**同时给宽度**把体积夹住：`no wider than a seventh of the frame width`。

顺带一处：**分区色彩要报「每块占多少」**。这张我写了 `violet and magenta ... cyan shading into acid green ... yellow running down through orange into red`，听起来是三个区，实际是一条完整光谱——返图 `sat 0.390 → 0.561`，色带铺满了全画面。改成「三块 + 各自的面积」才收得住：`the violet zone takes the top left quarter, the cyan zone the whole right half, the hot red zone only the bottom right corner`。

### 7.4 题材只改三样东西，不要另写一套

反推不同题材时，真正要换的只有三样，其余全部沿用：

1. **纹理的载体**：照片靠胶片颗粒，纸本靠纸纹与吸色边，印刷靠网点与错版，数字平涂靠零纹理。换错载体，整张图立刻变成另一种媒介。
2. **「效果」的物理替代**：写不出「虹彩」就直接写它是什么——两种状态的分界线（`the surface changes from magenta to cyan along a single hard seam, and each colour keeps its full strength right up to that seam`）。写不出「发光」就写光落在哪个面上、暗成什么样。
3. **颜色的持有者**：同一句话在不同题材里要换个持有物。金属上的红是反射，玻璃上的红是透射，纸上的红是印上去的颜料——`a red reflection in the chrome` 与 `a red band printed on the paper` 会出成两张完全不同的图。

其余（机位四要素、比例尺、分区占比、两处锚、明度档）一个字都不用改，因为它们是**画面**的性质，不是**题材**的性质。

### 7.5 「对了，但不震撼」——先量三种密度，别加形容词

返图「还行，但没原图震撼」时，唯一的错误反应是往里加形容词（epic / awe-inspiring / spectacular）。模型没有「震撼」这个概念，它只有像素。**震撼在数值上是具体的，而且有两种，用错了手段就越改越远。**

| 类型 | 数值长相 | 画面长相 | 靠什么造 |
|---|---|---|---|
| **密度型** | `flat` 低（0.33 一档）· `strong` 高（0.27 一档）· `nw` 极低 · `sat` 低 | 城市、人群、碎石、树叶、瓦片——同一块面上成百上千个小单元 | 单元变小、边变硬、重复数量报出来 |
| **动势型** | `flat` 高（0.64）· `soft` 高（0.91）· `strong` 低（0.09）· `sat` 低 | 坠落、冲撞、拖影、倾斜——糊的是背景，主体仍是锐的 | 整幅 roll、同向平行拖影、不给地平线 |

两张实测：塔顶俯瞰 `flat 0.331 / strong 0.273`，坠落格斗 `flat 0.643 / soft 0.911`。**同一个「震撼」，数值几乎相反。** 所以第一步永远是跟参考比这三个数，差一倍以上就不叫「差一点」，是机制错了。

#### 密度型：把单元写小，把边写死

塔顶那张我第一版返图 `flat 0.331 → 0.605`、`strong 0.273 → 0.143`、`sat 0.292 → 0.561`——三个数一起坏，读起来就是「楼变少、边变软、青蓝糊成一片」。改法不是「更细致」，是三条可数的东西：

1. **单元尺寸写成可量的**：`each window is a rectangle four pixels across at this distance`、`each balcony rail is a single one-pixel line`。写 `many windows` 会得到十几个大窗户。
2. **重复数量报出来**：`a hundred or so separate pieces`、`thousands of small rectangles`。数量词是密度唯一的把手。
3. **硬边写死**：`each surface a flat panel with no gradient across it`、`every edge cut like a blade`。少这一句，`soft` 会往 0.85 跑。
4. 顺手把 `sat` 压回去：密度图里颜色必须**只在少数几处**，不然色块会把碎片吞掉。

#### 动势型：糊背景，不糊主体

反过来，坠落、冲撞这类图**不能要密度**。坠落格斗参考 `flat 0.643`、`soft 0.911`——它本身就是糊的。写法三条：

1. **整幅 roll，并且写在 summary**：`the entire frame is rolled about thirty-five degrees off level, so every vertical leans`。在 object 里单独写「这栋楼歪了」不够，那样别的楼还是正的。
2. **拖影要指定方向和形状**：`pulled into parallel bands of one uniform grey that run in the direction she is falling, smeared rather than blurred, each streak a hard-edged band with no gradient inside it`。`smeared rather than blurred` 这句是关键——它把「拖影」和「虚焦」分开。
3. **地平线与天空一起删掉**：`there is no horizon in the picture and no sky at all`。留一条地平线，倾角立刻被读成「相机歪了」而不是「她在坠落」。

#### 两种不能混

- 把动势图当密度图写 → 拖影消失，变成一张静态的糊图。
- 把密度图当动势图写 → 城市被拖成灰带，密度归零。

`flat` 是这两类的分水岭，判完再动笔。

### 8.3 宇宙投影图 → 1792×768（2026-11-18）

参考图 1200×1918 竖幅手绘水彩。改成 21:9，所以第一件事不是改句子，是回答「竖着成立的东西横过来还剩下什么」。

|---|---|---|

五问的答案：

1. **她在做什么**：抱着一台投影仪漂浮，投影仪对着右上方射出；一只手抓着结构杆。
2. **东西在哪**：左侧一整面飞船外壳从顶到底；她中偏左；楔形向右上出去；右上月球；右缘另一颗月球的边缘；右下圆盘站体；底边缆线。
3. **怎么动的**：身体与竖直约成三十五度，头朝左上、靴子拖向右下；楔形两条边是直的、越走越宽——**动势靠「角度 + 楔形展开」表达，不靠 `dynamic` 这类词**。
4. **光从哪来**：太阳在画外右侧，只照到朝它的平面，一米内就死；楔形内部**一点光都没有**，它是「日光上挖的洞」，不是「射进来的光」。
5. **不对劲的地方**：靴底结着灰土，可这地方没有任何土。

三处新学到的：

1. **竖改横不要平移构图，要重新分谁贴边。** 原图她占近四成高、位于中下；横版里她只能到三分之一高（G25），于是把「大」让给左侧外壳（贴满左边五分之一、从顶到底），她改成「人在中偏左、器物向右上冲」。
2. **水彩线稿题材不要用胶片颗粒。** 默认的 `35mm ISO 1600 + coarse grain` 会把线稿揉掉。这个题材的颗粒是纸纹：`the tooth of the paper reads as an even fine speckle ... ink lines sink into that tooth`。**是题材决定颗粒形态，不是放弃颗粒。**
3. **「虹彩」不能写成一个形容词。** 写成「同一物体两种状态的分界线是直线」：`the big moon ... warm grey with brown craters; inside the wedge the same moon blooms into magenta, violet and cyan ..., and the border between the two states follows the wedge edge as one perfectly straight line`。只写 `iridescent` 会得到一片渐变。

产物 `_cosmos/rev-1792x768.json`，957 词，`lint` 0 FAIL 0 WARN。

两处教训：

1. **`near-black with a cold blue bias` 这半句会抬亮。** 写「偏冷的近黑」，模型给的是「深藏青」。要真黑就写 `the deepest tone in the frame is the ink itself, and no light reaches inside that wedge`——**把黑锚在墨这个具体材料上**，别给黑加色调限定。

## 九、这个模块不做什么

- 不给「一键复刻」。反推的产物是**一份能改的草稿**，不是一张能直接发的图。
- 不做相似度评分。有了分数就会去凑分数，而凑出来的分数与「像」不是一回事。
- 不把单张参考图升格成规则。这条写在开头，也写在 `aesthetic/h-style-extraction.md` 里。

## 十、外部手册里吸收的四条（2026-11-18）

用户拿来一份高人整理的《图像反推与角色复刻提示词方法论》（跨模型通用手册，114 行）。逐条比对后，四条是真长在我们缺的地方，两条不吸收。

### 吸收 1：视角证据句（最值钱的一条）

「只写 `overhead` / `top-down`，模型会退化成普通平视站姿。要写成具体角度，**并补足只有这个角度才看得见的画面事实**（头顶、双肩、被透视压缩的手臂、脚下地面或鞋底）。」

这条同时解释了 §7.2 那个三视图错误：我给了刀的二维落位，没给「只有这个视角才看得见什么」。**视角不是形容词，是证据**——写了视角就要写出这个视角独有的画面事实，模型才肯真的把机位挪过去。

### 吸收 2：Layout 里每处文字单独一个框

我们 `layout.md` 原来只写了「`text` 字段必须是真实字串」，没写拆框。已补进 `layout.md` §3：多处文字合并进一个全屏大 `text` 框会摊薄注意力、直接掉字。

### 吸收 3：成片的前景要拆成独立 `object` 框并量化密度

花海、落叶、飘雪这类「要密」的东西，只在 summary 里顺带一句会出得很稀。已补进 `layout.md` §3。

### 吸收 4：返图诊断表里我们缺的两行

| 症状 | 根因 | 修法 |
|---|---|---|
| 动作方向 / 支撑点错位（单腿支撑的高踢被画成单手倒立） | 动作描述含糊 | 写清哪只脚/手触地支撑、躯干倾角几度、哪条腿抬起及朝向 |
| 大俯拍变成平视站姿 | 用了 `overhead` 或缺少该视角可见部位 | 改具体角度 + 补视角证据句（吸收 1） |

### 不吸收 1：结尾写 `No watermarks.`

手册自己前后矛盾：§二.2 要求「零防御性否定词」，§一.7 又要求「末尾统一以 `No watermarks.` 收尾」。按本包口径，`no X` 会被正向激活，去水印靠**不给水印留位置**（画面元素自己占满边角），不靠写一句否定。

### 不吸收 2：NAI 保留质量词

手册写「NAI 保留 `{masterpiece}, {best quality}`」。这与 `real-corpus.md` 的实测一致（NAI 用户 81.5% 都写），但这是**模型差异**，不是通用规律——MOSS 一侧仍然不写质量词。把它当「NAI 专属」而不是「通用做法」才对。

### 顺带对齐的一处：分辨率表

手册给的 16 倍数表比我们原来的口径更细。现在统一到 `align_bboxes.py dims` 的算法（基准面积 1536×1024、长边上限 1664、结果吸附到 16），手挑表与脚本算出来的必须是同一组数，否则下次又是两份答案：

| 比例 | dims 现算 | 备注 |
|---|---|---|
| 2:3 | `1024×1536` | 竖图默认档 |
| 3:2 | `1536×1024` | 横图默认档 |
| 16:9 | `1664×928` | 手册写 `1536×864`，同族合法；dims 按面积算给 1664×928 |
| 21:9 | `1664×704` | 手册写 `1536×704` 或 `1664×704`，取后者 |
| 9:16 | `928×1664` | 手册写 `864×1536`，同族合法 |

我们更早用过 `1792×768`（21:9，也是 16 的倍数）——合法，但现在以 `dims` 的输出为准，别再手写第三个数。
