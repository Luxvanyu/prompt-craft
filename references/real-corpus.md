# 一万条真实提示词：别人到底怎么写

<!-- back -->
返回：总入口 `SKILL.md`｜相关 `references/lexicon.md`（查词；§八 是 64 条场景串）、
`references/scene-anatomy.md`（切片分析，参考而非骨架）、`references/word-budget.md`（预算）

这份文档只做一件事：拿 **10958 条写完并出过图的完整提示词**做机械统计，
量出「真实世界里大家怎么写」，然后回答一个问题——
**本包那些规则，哪几条是普适的，哪几条只是 MOSS 专属。**

**来源与性质**：两个社区公开图包（`nai5_community_pack` 4096 条、
`nai45_community_pack` 6862 条），每条含完整正向、负向、子提示词、
出图参数和原图。**全部是 NAI 语法，没有一条在本包实测过。**
所以下面写的是「他们怎么写的」，不是「这样写一定对」。

数据不入库（42 MB）。要查先跑一次：

```bash
python scripts/fetch_lexicon.py --packs      # 下载两个图包到 scripts/.lexicon
python scripts/corpus.py                     # 看概况
python scripts/corpus.py --find 侧光         # 看别人怎么用这个词
python scripts/corpus.py --show 3 --rating safe
```

## 一、六个能直接校准直觉的数

| 指标 | NAI v5（4096 条） | NAI v4.5（6862 条） |
|---|---|---|
| 正向 tag 数（去掉权重壳后） | 中位 **33**（p25 24 / p75 47） | 中位 **29**（p25 19 / p75 42） |
| 画师标签数 | 中位 **6**，均 6.1，p75 **9**，最多 34 | 中位 **5**，均 6.8，p75 **11**，最多 84 |
| 一个画师都不写的 | **18.4%** | **22.4%** |
| 画师串出现在第一段 | **30.0%** | **31.4%** |
| 第一段是人数词（`1girl` / `solo`） | **34.2%** | **39.3%** |
| 第一段直接写内容 | **35.8%** | **29.1%** |
| 画师串的相对位置 | 中位 **0.06**，p75 0.18，前四分之一内 **82.3%** | 中位 **0.04**，p75 0.12，前四分之一内 **87.1%** |
| 正向均字数 | **720** 字符（中位 626） | **621** 字符（中位 536） |
| 负向字数 | 均 **1057** 字符 | 均 **723** 字符 |
| 负向模板重复率 | **57.3%** | **65.2%** |
| 多条子提示词（`characterPrompts` > 1） | **41.1%** | 27.0% |
| 含英文长句（≥8 词）的条目 | **21.2%** | **25.1%** |

**三个数值得记一下**：

1. **中位 33 个 tag**。本包 `word-budget.md` 的标准档是 600–800 字符
   英文 / 约 35 个标签位——**这两个数是对上的**，不是拍脑袋。
   宽档 850–1100 对应 p75 的 47 个，也合理。**超过 60 个 tag 就进极端尾部了。**
2. **开头三分天下**：第一段是画师串的 30.0%（v5）/ 31.4%（v4.5），
   第一段是 `1girl`/`solo` 这类人数词的 34.2% / 39.3%，第一段直接写内容的
   35.8% / 29.1%。**没有一种写法是压倒性的**，三种各占三分之一左右。
   但画师串的相对位置很靠前——中位 0.06 / 0.04，**八成以上落在前四分之一**
   （82.3% / 87.1%），p75 也只到 0.18 / 0.12。
   所以准确的说法是：**画师串位置靠前，但不必是第一个词**。
3. **负向是模板，不是创作**。负向平均 1000 字符，其中 57–65% 是完全相同的
   复制粘贴。也就是说：**没人每次重新想负向**，都是同一份底噪反复用。
   这一条直接支持本包「负向只写这一张图独有的问题」的立场。

## 二、被印证的三件事（本包的规则在别人那儿也成立）

### 2.1 空转形容词真的没人用

在 64 条成品场景串里：`beautiful lighting` **0** 条、`dramatic atmosphere` **0** 条、
`moody lighting` **0** 条。在一万条图包里，质量词只有固定那几个
（`masterpiece` / `best quality` / `very aesthetic` / `absurdres`），
**没有一条写「电影感光线」「氛围感」这类空话**。

本包「形容词空转要删」这条，**不是洁癖，是别人也在做的事**。

### 2.2 加权的东西不超过三成

64 条场景串平均 13 段，权重只占 3–4 段（平均 2.9 处，60/64 落在 3–4）。
一万条图包里 `1.5::` 以上的顶格权重极少，绝大多数权重落在 0.5–1.5 之间，
还有大量**负权重**（`-2::multiple views::`、`-5::text::`）用来「压掉」不想要的。

### 2.3 结构位置比权重对抗更常用

v5 图包里 95.3% 用了 `n::文字::` 权重壳，但**权重档位的分布集中在 1.2–1.5**，
真正靠权重打架的（`-5::`、`5::`）只出现在少数实验性条目里。
主流做法是：**把想要的东西写清楚、写具体、写在前面的位置**，
而不是「权重拉满」。

## 三、要修正的三件事（本包的话得加限定）

### 3.1 「不用质量词」是 MOSS 专属，不是普适

| 质量词 | v5 出现率 | v4.5 出现率 |
|---|---|---|
| `best quality` | 55.9% | **81.5%** |
| `very aesthetic` | **64.5%** | 63.0% |
| `masterpiece` | 63.3% | 59.0% |
| `absurdres` | 42.7% | 55.8% |
| `amazing quality` | 38.2% | 45.9% |
| `highres` | 37.4% | 32.3% |

NAI 用户**八成都在写质量词**。所以本包 `lint.py` 把 `masterpiece` /
`best quality` / `very aesthetic` 列进 MOSS 禁用表是对的，
但**文档里要说清这是「MOSS 不吃这套」，不是「质量词没用」**——
换个模型（NAI / SD / Flux）它们是真的有用。

### 3.2 「3 个画师」偏保守

本包和用户习惯用 3 个画师标签（`@4x0style, @k4nz4r1n, @dabaitu`）。
实测中位是 **6 个**，p75 是 **9 个**（v5）/ **11 个**（v4.5），12 个以上的还有 13.7% / 24.8%。
**3 个不是「标准」，是「够用的下限」**——想更贴某个风格族，加到 6–10 个是常态。

### 3.3 「35 个 tag」方向对，但别当硬上限

中位 33，p75 是 47。**35 是「典型」，47 是「偏多但正常」，60 以上才是极端。**
MOSS 的实际容忍度另说（那是模型问题，不是这些数据能回答的）。

## 四、一个此前没写进本包的结构：子提示词

v5 图包里 **41.1%** 的条目用了不止一条 `characterPrompts`：

```
基础段（管全局）：1girl with dog, artist:xxx, ..., close up, ...
  char1：black dog, black fog around dog, 2::(greyhound, long neck, slim legs)::
  char2：girl, hanfu, hair rings, floating hair, very long hair, ...
```

**机制**：基础段管「画面怎么拍」，每个 `charN` 管「这个角色长什么样」，
模型把两边分开算再合成。这是「多角色不串味」的工程解法——
**不是靠文字描写说清谁是谁，是靠输入结构切分**。

对应到本包：`multi-character.md` 讲的是 MOSS 的做法（一句话里用
位置状语区分），这条是 NAI 的做法（结构化切分）。**两者不能互换**，
但如果目标模型支持区域/分块输入，这条比文字描述可靠得多。

顺带一个分布（v5）：r18 条目里用 2 条以上子提示词的占 **51.8%**、r18g **60.7%**，
safe 只有 **14.9%**——**角色越多、越需要切分**。

## 五、语法使用率（哪种写法真有人在用）

| 语法 | v5 | v4.5 | 说明 |
|---|---|---|---|
| `1.5::文字::` 权重壳 | **95.3%** | 80.6% | v5 主力语法 |
| 小数权重（`0.65::`） | 91.4% | 73.2% | 大量落在 0.5–1.5 |
| `{}` 花括号 | 11.4% | 30.6% | v4.5 常用，v5 退场 |
| `[]` 方括号 | 4.7% | 38.2% | 同上 |
| `(word:1.2)` 括号式 | 0.7% | 1.4% | **几乎没人用** |
| `\|\| a \| b \|\|` 序列块 | 0.7% | 1.2% | 少，但都是分格/多视图 |

**`(word:1.2)` 是 SD 语法，NAI 这边基本被 `n:: ::` 取代了。**

## 八、这份数据不能证明什么

1. **不能证明「这样写能出好图」**。图包是「被人挑出来公开的」，
   有幸存者偏差——失败的尝试不会进图包。
2. **不能证明因果**。中位 33 个 tag 不等于「写 33 个就好看」，
   只说明「写 33 个是常态」。
3. **不能跨模型外推**。NAI 的语法、质量词、参数，对 MOSS / SD / Flux
   的有效性完全不同。这份文档的定位是**校准直觉**，不是**配方**。
4. **画师数量那条尤其可疑**。v4.5 有 24.8% 写了 12 个以上画师，
   那是「风格融合实验」的做法，不是常规操作。中位 5–6 才是常规。

## 九、第三方实测：字数与「玄学词」

来源是 B 站 UP 主「星辰大海Rest」的模型能力测试合集，两期都是**本地 MOSS、同 seed、同参数、只改提示词**，原文可在视频简介里核对。**证据等级：第三方实测，不进 casebook 的 G 编号**（那不是本包自己跑的数）。

### 9.1 字数：500 字是「人物定型」的门槛

设计：6 个场景 × 6 档字数（50 字一路到 2500 字），同 seed，短档是长档原封不动的开头，只往后补细节，共 36 张主图，一张不挑不修。

- 先排除截断：分词器实测六档 token 是 32 / 137 / 319 / 646 / 959 / 1550，一路递增没撞顶，2500 字是完整读完的。
- 相邻档像素差：50→500 字变化最大，之后明显趋缓；低档平均 55.7，高档 31.5，**差 1.8 倍**。
- 变化分两段：低档连人物长相、服装都在重抽；**500 字左右人才定下来**，之后才是同一个身上堆细节。

结论是「不是越长越好」，500 字前后是分界。

对照本包：`word-budget.md` 紧档 450–550 英文词，按信息量大约相当于中文 700–900 字，**已经在这条线之上**；标准档 600–800 词更宽。所以三档预算不用改。但这个实验给了下限一个比原来更好的理由——低于门槛不是「细节少」，是**同 seed 下人物会变成另一个人**。

### 9.2 玄学词：改的是姿势，不是画质

设计：同场景、同 seed、同参数，只改提示词写法，11 张对照图，然后打乱顺序盲评。

- **同 seed 画两次像素差 0.00** —— MOSS 零随机。这条很实用：之后任何画面差异都只能来自提示词，不能赖种子。
- 加玄学词（`masterpiece` / `best quality` / emoji / 「求求你画好看点」）画面全变了（差 19.6–41.5，连长串乱码都变），但盲评**画质没有高下，变的是姿势和角度**。
- 作者自己的三句总结：模型零随机；玄学改姿势不改画质；把场景讲具体比堆十句咒语管用。

对照本包：`lint.py` 关 5 禁质量词这条，这里给了比「MOSS 不吃」更硬的机制——质量词没有提升画质的能力，它只是换来一次构图重抽。（推测：它在 prompt 里占了位置，注意力被挪走了。）这同时也解释了为什么加了质量词常常「感觉变好了」：变的是构图，不是清晰度；换一张脸重抽一次，总有抽得更顺眼的时候。
